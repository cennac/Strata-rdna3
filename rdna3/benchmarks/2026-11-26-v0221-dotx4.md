# v0.2.21 CPU dot-x4 paired test (b506, 2026-11-26)

Upstream v0.2.21 makes four-row CPU dot sharing opt-in (`STRATA_DOT_X4=1`) rather than default. This test toggles only that environment setting on the migrated dual-gfx1100 GSQ-RCO IQ3_XXS profile; the binary and weights remain identical.

The candidate matches all 26 frozen raw/sampled/continuation probes and the 33/23 forced rollbacks, with no new failures in the six-case, 128-output objective screen. That capped screen is not a full quality score. Scored loads use three alternating pairs (off/on, on/off, off/on), reverse task order in the middle pair, 1024 tokens per request, no prompt/cache hits, presence penalty 1.5, temperature 0 and seed 42. Single request uses both cards; dual throughput includes first-token wait and requires admission of both slots in the same batch.

The predeclared adoption gate requires at least 2% geometric mean paired gain, no lane more than 2% slower, and at least two wins for every lane counted as a >=2% gain. Outcome: **not adopted**. Geometric mean change: **-0.89%**. The default template keeps the upstream setting off.

Code dual throughput depends strongly on task order in both arms: it is lower when it is the first batch after a fresh load. Full per-pair values are retained; warm throughput is not a guarantee for the first call. This experiment does not attribute that order effect to a particular cache, graph capture or CPU operation without a separate profile.

All 36 scored requests completed in full. The original production source configuration and binary were restored, the test port was closed, and no telemetry guard fired. Temperatures and the minimum available RAM are in the sanitized JSON. Private deployment paths and raw responses remain outside Git.
