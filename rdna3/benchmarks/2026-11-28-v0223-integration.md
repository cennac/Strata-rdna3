# Strata v0.2.23 RDNA3 migration — b525/b526 (2026-11-28)

Upstream v0.2.23 was imported on `vendor-0223` and merged into the adopted dev/0.2.22 profile on
`dev/0.2.23` (merge `90551fa`). The upstream engine sources report 0.1.70; the fork's carried
changes (pool-queue serve thread, rdna probes, exact MMVQ/GR switches, penalty-aware pipelining)
merged cleanly — the three files both sides touched (`CMakeLists.txt`, `expert_source.hpp/.cpp`)
auto-merged, and only `AGENTS.md` needed the fork-side resolution used by the v0.2.22 merge.

Unlike the v0.2.22 migration this round benchmarks **GSQ-RCO IQ3_S** (the profile serving on 66
at measurement time), with the blower card's 2300 MHz top-clock limit in force for every load.
Numbers from b521–b524 (limit inactive) are not comparable.

## Throughput (tok/s; single = one request on both GPUs, dual = two concurrent, total over batch wall)

Same pack and expert-profile seed, one fresh load per arm, two passes of the four workloads each,
1024 output tokens, greedy, seed 42, presence 1.5, caches disabled, `--pool-workers 12`.

(load order: arm pass 1 / pass 2; the serving column is the direct live measurement of the same
day, cold round then warm round.)

The v0.2.23 optimized build is at parity with the adopted v0.2.22 build: every warm-pass lane is
within ±2.5% (Chinese single +1.1%, Chinese dual −3.1%, code single −1.4%, code dual −0.1%); only
the first-burst Chinese single (cold expert cache) moved more, which the previous rounds showed to
be load-order noise. The upstream engine changes between v0.2.22 and v0.2.23 touch only two files
on the Qwen/HIP path (`src/prefill/moe_fused_iq.cu`, `src/kernels/cpu/native_expert.cpp`) and bring
no measurable stock speed change: stock v0.2.23 (54.0–56.1 / 99.3–100.8 / 65.3–68.2 / 100.0–100.9)
matches the v0.2.22 stock baseline from b521 within noise on this workload.

The optimized build still trails the serving legacy 0.1.43 by roughly 2–4% on the single lanes and
6–10% on the dual lanes under the enforced clock limit — the same structural gap attributed in the
IQ3_S attribution rounds (per-step CPU-expert wait on single, retained-draft ratio on dual).

## Reproduction and evidence

Window harness `66/artifacts/strata-v0223-b525` (stock versus optimized) and `…-b526` (optimized
0.2.23 versus optimized 0.2.22, environment and arguments identical, only the binary differs):
`make_plan.py` reads the serving runtime config and production pins live, `check.py` runs the
offline plan/rejection suite, `campaign66.py` stages, verifies, prefights and drives the bounded
systemd window. Evidence (per-burst rows, engine logs, telemetry, hashes) under each harness's
`evidence/`; the b526 record also carries the restore verification. No quality gate was run this
round: the merge keeps bit-identical engine paths for the carried switches, but adoption still
requires the frozen-probe and rollback gates before any production change.

Production (legacy 0.1.43, IQ3_S) was restored and verified after both windows: loaded and idle,
binary and configuration hashes unchanged, the side port closed, no kernel faults, and the blower
clock limit re-confirmed in force.
