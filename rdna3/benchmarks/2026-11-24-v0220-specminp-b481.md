# --spec-min-p 0.5 against 0.35 on the adopted profile: more drafts, no gain

b481 paired the [adopted profile](2026-11-24-v0220-grdna-adoption.md) with `--spec-min-p 0.5` against the same
profile with `0.35`, on dual RX 7900 XTX. Same binary, environment, expert-profile seed and cache budgets; the draft
threshold is the only difference. A lower threshold lets the draft layer add another guess with less confidence.

## Quality

Both arms keep the adopted profile's reference shape (only raw Chinese greedy probes differ from the older reference;
sampled and code probes match), the objective suite has no new failures and the scored-text checks pass. The arms
differ on one raw probe (`zh-batch`) and in forced rollbacks (Chinese 33 against 28, code 23 against 22), which was
allowed for this screen because an extra guess can change which window size verifies a token.

## Drafts and speed

Three alternating fresh-load pairs; pair 2 reversed the workload order. All 36 scored requests finished at 1,024
output tokens with caches off. Draft counters are summed over the scored requests of each language.

| Prompts | Control: accepted / offered | 0.35: accepted / offered |
|---|---:|---:|
| zh | 1520 / 2319 (0.655) | 1566 / 2565 (0.611) |
| code | 1833 / 2275 (0.806) | 1833 / 2362 (0.776) |

Not adopted: Chinese single gained 1.96% in two of three pairs, below the bar, and code single lost 2.51%. The
lower threshold offers more guesses (Chinese 2,319 to 2,565) at a lower acceptance rate (0.655 to 0.611), so the
extra verified rows cancel most of the extra accepted tokens. The profile keeps `--spec-min-p 0.5`. Production
restoration was verified after the window; nothing was deployed. Per-pair values:
