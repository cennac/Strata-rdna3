# Strata v0.2.20: matched-residency integration and gfx1100 exact subset

On two RX 7900 XTX cards (26/22 layer split, ROCm 10.1) with Qwen3.8-Flash-Next GSQ-RCO IQ3_XXS, the four-switch exact subset passed the quality and speed gates in b464. **Chinese dual improved 6.34% in the median and was faster in all three pairs.** Use this as an opt-in development profile; the result does not qualify automatic cache sizing or a production rollout.

## Three-way comparison

Each cell shows median **tok/s / TTFT in ms**. Historical production has three length-matched bursts per workload; stock b460 has two fresh loads, and the b464 exact candidate has three. One request uses both GPUs; single-lane throughput is engine decode speed. Dual-lane throughput is total emitted tokens over batch wall time, including first-token wait. TTFT is separate. The scored requests used 1,024 output tokens with caches off. The three columns are from different windows; use only the b464 paired comparison for adoption.

| Workload | Historical production 0.1.43 | v0.2.20 stock (0.1.66) | dev/0.2.20 exact (0.1.66) |
|---|---:|---:|---:|
| Chinese single | 139.10 / 253.8 | 64.50 / 779.3 | 117.70 / 293.7 |
| Chinese dual | 185.75 / 960.8 | 112.69 / 1581.1 | 171.58 / 590.6 |
| Code single | 195.50 / 234.1 | 79.75 / 707.5 | 156.50 / 277.4 |
| Code dual | 235.83 / 873.2 | 106.99 / 1434.2 | 224.54 / 538.4 |

The stock engine ran unmodified with upstream tuning defaults and no compatibility fallback. Its code dual repeats were 114.23 and 99.75 tok/s; the median is not a tight repeatability bound. The exact profile is faster than stock in all four workloads, but still below historical production throughput in all four.

## Integration and quality evidence

- **b459:** the vendor and integrated v0.2.20 builds both succeeded. The integrated build with automatic expert-cache sizing completed raw and sampled self-checks but differed from the frozen [0.1.65 reference](../reference-0.1.65.json) on 11/14 raw and 10/12 sampled streams. Forced rollback counts were 34/25 instead of 35/21 (Chinese/code). Scoring did not start.
- **b462:** the same binary passed all 26 token and finish comparisons and both forced rollback counts at matched residency. The explicit expert-cache budget of 8624 reproduced 12,905 / 9,623 populated slots on the two GPUs, versus 12,921 / 9,623 with b459 auto sizing. The CLI value is a byte-budget input, not a slot count. Matching the budget and actual capacity removed the observed differences in these probes; it does not prove which individual experts or arithmetic paths caused them. This was a quality-only run.
- **b463:** validated the same reference again and passed the six-case objective gate. A Chinese dual request in the second scored load stopped at 713 tokens; the run has no eligible aggregate scores. That request was not replaced or normalized.
- **b464:** both arms matched all 14 raw and 12 sampled probes, including seeded sampling, live-prefix continuation, forced rollback (35/21), and two-slot batching. The fixed-zero graph was observed at both split stages, and penalty-aware behavior was verified from traces. Both arms passed objective cases 19 and 23, with no new failures; the other four cases were not answered correctly. The exact candidate's BF16 rows, INT8 lane-cell scoring and v2 merger were observed in both stages' graphs. `SMALL_UNR` changes a runtime argument on the observed batch GDN A/B path; graph symbols do not distinguish that argument value.

## Paired result and reproduction

All six scored loads used the same integrated engine from `53b8629`, fixed profile seed and cache budget. The fresh-load order was off/on, on/off, off/on, with workload order reversed in pair 2. Each load ran the four workloads; all 36 scored requests finished at length. Dual bursts confirmed that both slots were admitted into the same pipelined batch.

| Workload | Control tok/s | Exact tok/s | Throughput change | TTFT change | Faster pairs |
|---|---:|---:|---:|---:|---:|
| Chinese single | 119.40 | 117.70 | −1.42% | +1.38% | 1/3 |
| Chinese dual | 161.36 | 171.58 | +6.34% | +0.08% | 3/3 |
| Code single | 156.20 | 156.50 | +0.19% | +1.35% | 2/3 |
| Code dual | 222.66 | 224.54 | +0.85% | −0.10% | 3/3 |

Chinese dual was the only workload to meet both the three-pair and ≥2% median improvement requirements. No workload lost more than 2% throughput or regressed more than 5% in TTFT. Code dual was slower in pair 2 for both arms, so the median is more useful than a single load.

Use the development [template](../dual-xxs.template.json) with the same weights, expert-profile seed, split, and fixed-zero/penalty profile. The reproduction phases use explicit `--expert-cache` budgets: **8624** for raw and sampled validation (12,905 / 9,623 slots), **8012** for objective (11,976 / 9,623), and **8013** for scoring (11,977 / 9,623). Verify actual slots and profile fill rather than assuming the budgets transfer to another rig. The control adds no exact overrides; the candidate adds only:

```text
STRATA_MMVF_ROWS=1
STRATA_ATTN_LANECELL=1
STRATA_ATTN_MERGE_V2=1
STRATA_SMALL_UNR=3
```

Keep `STRATA_GFX11_DEFAULTS=0`, `STRATA_GR_FUSED=0`, `STRATA_GR_RDNA=0`, and the existing pins. The exact table was already present in v0.2.19. This test did not include TSUM, GDN split, long-prefill TOPK, WMMA, the parallel defaults, or the RDNA capture fix. Do not apply the four overrides alone to the unqualified automatic-cache configuration and claim the b464 result.

Production restoration was verified after each executed window: original live executable and config unchanged, test listener closed, no telemetry faults. No production deployment or `main` change. Per-load statistics and gate outcomes: [JSON](2026-11-23-v0220-exact.json).
