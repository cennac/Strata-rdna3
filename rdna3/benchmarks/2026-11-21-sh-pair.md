# Shared-expert gate/up pair launch: probe-pinned, partial coverage, screen incomplete

**Decision: keep `STRATA_LAB_RDNA_SH_PAIR` off.** The merged launch is bitwise-correct everywhere it engages and the predeclared screen could not complete (one scored burst ended early), but the decisive fact is measured coverage: only 4 front and 2 final layers have a same-type IQ4_XS gate/up pair, so the merge removes ~12 nodes per window pair (~0.7% of graph nodes) — far below the 2% adoption bar this screen was designed to test.

## What changed

The shared expert's gate and up projections are two adjacent `native_mmvq` launches reading one q8_1 image (`shared_expert.cu:229-234`). The existing `native_mmvq_pair` launcher only supported Q8_0; the change adds an IQ4_XS branch (the exact multi path the solo dispatch takes, ROWS=1 grid `2*n_out`, TS mirrored) and ORs a new default-off env into the pair condition, so the pair is attempted on the doorbell path too — including under the adopted shared-expert fork. Layers whose gate/up types differ, and odd `n_out` shapes, fall back to the exact two solos. Three files on `9ba93ba` (+88/−8): `shared_expert.cu`, `native_mmvq.cu`, `rdna_kquant_probe.cpp`.

## The probe pinned two boundaries the analysis had guessed

`rdna_kquant_probe` now runs the pair against the native solo dispatch (probe mode 0) bitwise per column count, plus a captured graph replay, and prints `usedn`/`pairn` per case. Three isolated-build cycles on 66 produced the measured contract:

- **Even `n_out`: bitwise everywhere.** Shapes 640, 512, 10240, 2560 and the discriminating 642 (even, not a multiple of 4 — killing the odd-row0 hypothesis) all match both solo kernels at cols 1..8, captured replays included. Service gate/up shapes are even.
- **Odd `n_out` (641): not bitwise** (~1e-7 relative difference vs both solo kernels; root cause not chased). The guard blocks the pair there — the probe asserts that exact fallback.
- The opt-in **lab family's own pair** diverges from its lab solo at 642 (`pairl=0`) — a pre-existing lab property recorded by the probe but outside the engine contract (the lab is `STRATA_LAB_RDNA_KQUANTS`-gated and off in the template).

Two campaign attempts were correctly aborted by the probe gate before these boundaries were measured (r1: odd shapes failed; r2: the new 642 shape exposed the lab pair), a third by a harness parsing bug (GRAPH lines treated as case rows); none touched production beyond the verified restore.

## Gates that passed (b441-r4, clean binary `49e3985d…`)

- Probe exit 0 on both GPUs; `SUMMARY bad=0`; type-23 `usedn` exactly matches the even/odd boundary.
- Frozen raw: exact token IDs and `length` finishes identical across arms for all 14 requests (serial repeat, pw2, forced-rollback, two-slot batch, no-penalty; explicit 64-token penalty history). Forced mode: 32 Chinese / 23 code rollbacks in each arm.
- Positive-temperature sampling: exact repeats and prefix continuation identical across arms.
- Objective v7: no new failures (same five shared failures both arms).
- Graph gate: 24 matched buckets, each showing exactly one new `native_mmvq_multi_kernel` PAIR instantiation, decreases only from mmvq kernels, deficit = 2 × pair count.

## Measured coverage and the screen

The graph evidence shows the pair engaged on **4 of 26 front layers and 2 of 22 final layers** (−8/−4 nodes per stage graph). The earlier node-count inference that motivated this round had attributed the pack's IQ4_XS multi-kernel nodes mostly to shared gate/up; they are mostly attention/GDN projections, where gate/up do not pair. With ~0.7% of graph nodes removable, the predeclared adoption bar (a workload faster in all three pairs, ≥2% median) is not plausibly reachable.

The scored phase ran p1 and p2-off/p3 fully valid; the p2-on Chinese dual burst ended at 541 tokens (`finish=stop`, the off-arm of the same pair completed 1,024). `score_rows` refused to score it and the campaign restored production. The 10 completed workload comparisons are pairwise noise (−3.7% to +4.6%, no consistent direction), consistent with the node arithmetic.

Production 0.1.43 was restored and verified after every attempt (same running executable hash, unchanged config, port 8101 closed, zero monitor faults). See the [structured record](2026-11-21-sh-pair.json).

## Standing state

The switch stays default-off and the worktree change is retained as probe-pinned machinery: if a future pack carries many same-type gate/up layer pairs, the merge is measured, bitwise-safe for even shapes, and ready to screen. Next candidates should come from the updated node analysis (per-layer launch sites with actual type attribution), not from aggregate histograms.
