# gfx1100 hipBLASLt table: faster long prefill, fails token parity

b466 held the b464 exact profile and the 0.1.66 binary fixed on dual RX 7900 XTX (26/22 split, ROCm 10.1, Qwen3.8-Flash-Next GSQ-RCO IQ3_XXS). Both arms used the same expert-profile seed and populated 12,905 / 9,623 GPU slots for the native long probes. The control set `STRATA_HIPBLASLT_TABLE=off` without an explicit table; the candidate used the upstream `gfx1100-hipblaslt-100401.txt` by explicit path. No other tuning changed.

These are **diagnostic** prompt times from four requests per length in one fresh native load per arm (serial, repeat, normal and forced pipeline), not three-pair scores or API TTFT. All input tokens were fresh. Each stage recorded the same 8,191 or 16,383 token chunk in both arms; the last prompt token is handled separately. The candidate recorded 776 successful hipBLASLt submissions and zero counted fallbacks in the long-request states at each length; temporary startup states are excluded. Zero counted fallbacks does not imply all prompt work ran through hipBLASLt.

Both arms passed the 26 frozen short probes (including forced rolls 35/21), the fixed-zero graph and penalty-path checks, and the six-case objective gate (cases 19 and 23 correct in both arms). All long probes finished at the 96-token cap and reproduced within each arm, but all eight cross-arm token comparisons differed. The first mismatch appeared even in serial and repeated runs. This fails the predeclared output-preservation gate; it does not establish that either answer is worse. Formal throughput/TTFT pairs did not run and no new scores are eligible. Neither historical production nor v0.2.20 stock was measured at these long prompt lengths in this campaign. The [b464 short-input comparison](2026-11-23-v0220-exact.md) remains unchanged.

No adoption or default profile change.
