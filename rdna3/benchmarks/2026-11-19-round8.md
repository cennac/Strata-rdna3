# 0.2.16 第八轮：现役与开发版的GPU阶段计时

本轮用于定位，不用于发布服务速度。启用 `STRATA_VERIFY_PROFILE=1` 后，共享专家不再分流，旧HC跨工作组融合也被禁用；固定专家自适应和后缀草稿关闭。每项768输出、1次，中文和代码各单请求，使用两张GPU。每请求容量131072，没有实际128K输入。

| 请求 | 现役重建 stage 0 / 1，ms/window | 开发版 stage 0 / 1，ms/window |
|---|---:|---:|
| 中文 | 10.28 / 10.95 | 12.14 / 12.78 |
| 代码 | 11.35 / 11.30 | 13.41 / 13.31 |

VRAM专家命中阶段接近：中文GDN第一阶段1.42对1.50ms，第二阶段1.19对1.28ms。共享专家、HC、部分投影和等待阶段均有差距，不能把全部退化归因于专家矩阵乘。`waitCPU`、复制与合并的边界也因实现不同而变化，单独一个等待标签不能当作完整根因。

这些均值包含实际执行与后来回滚的窗口，不是固定T的逐算子微基准。中文平均T为2.31对2.45，代码2.84对2.85；两版硬件队列上限仍分别为现役4、开发推荐3。该轮没有隔离队列数量、HC精度或所有内核布局，阶段差距只能用于选择下一项实验，不能据此证明单个源码改动的收益。

核对实际GGUF还发现：虽然词表输出头为Q5_K，GDN的qkv、输出投影及QSA的query仍大量使用IQ4_XS；部分QSA投影使用Q6_K，GDN gate和部分共享up使用IQ3_S。第七轮只验证Q5_K头，不能代替对这些稠密投影的迁移测试。后续将分别验证流调度和旧版K-quant专用核。

原始阶段数值和测试二进制哈希保存在[JSON](2026-11-19-round8.json)。测试结束已恢复现役0.1.43，配置哈希未变；本轮没有完整质量测试。
