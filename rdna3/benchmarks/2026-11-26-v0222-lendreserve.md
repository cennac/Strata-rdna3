# v0.2.22 split RAM reservation: no allocation effect on this profile (b512)

The new `STRATA_SPLIT_LEND_RESERVE=0` setting was checked on the migrated dual-gfx1100 GSQ-RCO IQ3_XXS profile with 96 GB RAM. It uses the same binary, weights, expert-profile seed and cache budgets as the default run.

| Phase | Primary / helper GPU slots, both settings | RAM complement, both settings | Prompt lend backing, both settings |
|---|---:|---:|---:|
| Frozen raw validation | 12905 / 9623 | 14.93 GiB | 7017 of 7017 slots, 11.35 GiB |
| Scored decode configuration | 11977 / 9623 | 16.26 GiB | 7000 of 7000 slots, 11.35 GiB |

The engine's effective environment carried the new setting. All 14 raw token probes and the 33/23 forced rollbacks matched the frozen reference. Neither allocation changed; every prompt lend slot remains RAM-backed. The reservation diagnostic was absent: the budget-limited allocation path where the setting matters was not entered. This system can retain both the full complement and the prompt copies.

No separate throughput score was produced for an unchanged allocation, and no new speed gain is claimed. The default reservation stays in the template. Reported gains on RAM-constrained NVIDIA rigs do not transfer to this configuration. The run restored production, left its configuration unchanged and closed the test port. b511 was an earlier prepared-only raw-probe plan; b512 also checks the scored-residency budget and is the executed evidence.
