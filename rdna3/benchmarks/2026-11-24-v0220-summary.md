# v0.2.20 campaign summary (b459–b479, 2026-11-23 to 2026-11-24)

This line integrates upstream v0.2.20 (engine 0.1.66) on `dev/0.2.20` and continues the dual RX 7900 XTX
optimization work from `dev/0.2.19`. The rig and protocol are unchanged: 26/22 layer split, ROCm 10.1,
Qwen3.8-Flash-Next GSQ-RCO IQ3_XXS, fixed expert-profile seed, 1,024 output tokens with caches off, seed 42 and
presence penalty 1.5. Single-lane figures are engine decode tok/s; dual-lane figures are total tokens over the batch
wall time, first token included. Every maintenance window verified production restoration (same live executable and
configuration, test port closed).

## Where the line stands

The adopted profile is 58% to 124% faster than stock, with first-token latency 63% to 65% lower. Against historical
production it is 8.0%, 4.4% and 15.7% behind on three lanes and 1.5% ahead on code dual. The production and stock
columns are reused from their own campaigns; the paired runs below are the adoption evidence.

The RDNA read was the largest single gain and the one that moved code dual past production. It changes the
summation order, so I gated it with a review declared before the window instead of token identity: the control still
matches the frozen [0.1.65 reference](../reference-0.1.65.json), the candidate differs only on the 7 raw Chinese
greedy probes (first difference at zero-based token 7 or 21, forced rollbacks 33/23 against 35/21), the 12 sampled
probes and 6 code probes match, the objective suite has no new failures, and the scored texts show no degeneration.
All four workloads were faster in all three pairs.

## Findings worth keeping

- **Automatic expert-cache sizing changes the output.** Engine 0.1.66 sizes the cache from a mean layer blob instead
  of the largest one, which moved the primary stage from 12,905 to 12,921 slots and changed 11 of 14 raw probes. An
  explicit `--expert-cache` value is a byte-budget input, not a slot count: 8624, 8012 and 8013 reproduce the
  reference residency of 12,905 / 9,623, 11,976 / 9,623 and 11,977 / 9,623 slots for validation, objective and scored
  loads ([b462](2026-11-23-v0220-exact.md)).
- **`STRATA_GR_FUSED` must stay out of the environment.** The upstream RDNA GR port allocates its fusion barrier
  whenever the variable is present, even as `0`, and the allocation lands inside the first verifier graph capture and
  aborts it. That was the whole reason the port had looked broken on gfx1100; the development profile had run without
  any RDNA hyper-connection read since the v0.2.19 merge ([b476](2026-11-24-v0220-grdna-diagnostic.md)). The
  one-launch fused read (`STRATA_GR_FUSED=1`) still needs a source change to allocate the barrier outside capture.
- **CPU pool workers: 12 is the optimum once the RDNA read is on.** Without it, 9 workers gained 2.4% to 2.7% on the
  Chinese lanes and lost 1.7% on code dual ([b475](2026-11-23-v0220-pool9.md)). With it, 9 workers lost on every lane
  ([b478](2026-11-24-v0220-pool9-adapted-b478.md)) and 16 workers lost 0.9% to 3.3%
  ([b479](2026-11-24-v0220-pool16-adapted-b479.md)): the shorter GPU window makes the CPU expert supply matter more.
- **The gfx1100 default tables are exhausted for this profile.** `STRATA_GDN_SPLIT` was output-identical but slower
  (Chinese dual −6.70%, [b473](2026-11-23-v0220-gdnsplit.md)); the seven-switch parallel batch-slot stack was neutral
  within 1.3% and its attention-row merge is inactive under KV streaming ([b474](2026-11-23-v0220-parallel.md));
  `STRATA_BATCH_SELF_COMMIT` disables pipelined MTP and was excluded; `STRATA_TSUM` aborts at load; the WMMA table
  mostly targets prefill.
- **The hipBLASLt 100401 table speeds up long prompts but changes their output.** Diagnostic prefill rose 4.1% at
  8,192 and 5.5% at 16,384 fresh tokens while all eight long streams diverged, so it was not adopted
  ([b466](2026-11-23-v0220-hipblaslt.md)).
- **One stock build is not reproducible enough on a single card for a token gate.** On one XTX with IQ3_XXS (512 input
  and 128 output tokens, three pairs), stock 0.2.20 decoded a median 56.08 tok/s against 60.85 for stock 0.2.19,
  with prefill flat at about 332 tok/s. The builds used different residency (10,457 against 10,493 slots) and draft
  acceptance (74.0% against 68.1%), and each build's own output drifted between loads even with residency frozen and
  adaptation off, so the gap is not attributed and the 9-worker comparison was not scored.

## Reproduction

The [template](../dual-xxs.template.json) carries the adopted environment: the earlier optimization set plus the exact
subset, `STRATA_EXPDEC=1` and `STRATA_GR_RDNA=1`, with `STRATA_GFX11_DEFAULTS=0` and 12 pool workers. Measurements
control residency with the explicit cache budgets above; the template leaves sizing to the engine. Each record lists
its binary hash, source revision, per-pair values and gate outcomes in an accompanying JSON file.

## What remains

Code single (−15.7%) and Chinese single (−8.0%) are the open gaps to historical production. Expert-cache hit rate is
already 98.9% to 99.8% on this profile and adaptive overlap is not available on a layer split, so configuration
changes have little left to give; closing the rest needs a per-window profile of engine 0.1.66 against the legacy
engine on this rig. Nothing was deployed and `main` is unchanged.
