# Parallel batch-slot stack on the exact + EXPDEC profile: parity holds, no gain

b474 paired the [b472 profile](2026-11-23-v0220-expdec.md) against the same profile plus seven switches of the gfx1100 parallel batch-slot stack: `STRATA_CKPT_POOL=1`, `STRATA_CKPT_POOL_READY=4`, `STRATA_SLOT_CKPT_MOVE=1`, `STRATA_SLOT_COPY_BATCHSYNC=1`, `STRATA_BATCH_GDN_GROUPS=1`, `STRATA_BATCH_ATTN_ROWS=1` and `STRATA_QSA_SLOTS=1`. `STRATA_SLOT_COPY_DIRECT=1` was already set. `STRATA_BATCH_SELF_COMMIT` was left out because the engine disables pipelined MTP when it is on, which this profile depends on. Rig and binary as in b472; the seven switches are the only difference.

## Quality

Both arms matched all 14 raw and 12 sampled probes of the frozen [0.1.65 reference](../reference-0.1.65.json) with forced rollbacks 35/21 and passed the graph and penalty-path checks; the objective gate showed no new failures.

## What the switches did here

The engine reported `batch rows in one launch: attention on, GDN on; the KV streams (--kv-resident), so attention keeps one launch per row` in the candidate and nothing of the kind in the control. The batch-window graphs have the same node counts in both arms (1,122 on stage 0, 963 on stage 1), and no request reported taking a checkpoint from the pool during validation. The attention-row merge is therefore inactive under KV streaming on this profile, and the checkpoint pool did not serve; the remaining stack switches are attested only through the live process environment.

## Paired result

Three alternating fresh-load pairs; pair 2 reversed the workload order. All 36 scored requests finished at 1,024 output tokens with caches off.

| Workload | Control tok/s | Parallel stack tok/s | Throughput | TTFT | Faster pairs |
|---|---:|---:|---:|---:|---:|
| Chinese single | 115.80 | 117.30 | +1.30% | +0.14% | 2/3 |
| Chinese dual | 166.43 | 165.37 | -0.64% | -0.47% | 1/3 |
| Code single | 157.50 | 158.10 | +0.38% | +1.10% | 2/3 |
| Code dual | 227.55 | 227.89 | +0.15% | -0.02% | 2/3 |

No workload improved in all three pairs or by 2%, and none lost more than 2%. The stack is not adopted; the development profile stays at the b472 configuration. With this screen the gfx1100 default tables are exhausted for this profile: the exact table is adopted in part, GDN split is slower, the parallel stack is neutral, TSUM aborts at load, and the WMMA table changes rounding and mostly targets prefill. Production restoration was verified after the window; no deployment or `main` change. Per-pair values: [JSON](2026-11-23-v0220-parallel.json).
